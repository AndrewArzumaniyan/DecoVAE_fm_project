# Decomposition experiments: seasonal decoder and noise branch of DecoVAE-FM

This folder holds mechanism-level experiments around the `decovaefm` model in the repository root.
They ask whether the trend / seasonal / noise decomposition is recovered, where forecast error comes
from, and how the predicted variance reacts to the noise in the input. The original package is used
unchanged: the variants below subclass `DecoVAEFM` or call its methods.

This is not the decisive experiment of the project plan (DecoVAE-FM against K²VAE and zero-shot
TSFMs). It prepares that comparison. Key results are summarised in [FINDINGS.md](FINDINGS.md).

## Layout

| folder | content |
|---|---|
| `period_decomp/` | per-window period estimation and period-aware decomposition (HP trend + Fourier seasonal at non-integer periods); synthetic benchmark; period detection on the pretraining corpus |
| `checks/` | numerical checks of the original decomposition and seasonal decoder without training; reproduction of `notebooks/debug_training.ipynb` against the known true distribution |
| `pinn/` | structural constraints (input representation, hard periodic decoder, smoothness and teacher penalties) on synthetic data |
| `fft_reconstruction/` | isolated original / amplitude-only / exact-frequency reconstruction ablation: native model and benchmark loss, 3 horizons × 3 seeds |
| `benchmark/` | model variants, synthetic and real data, training, evaluation, diagnostics, interventions, H1 data |
| `results/` | small summary tables used in FINDINGS.md |
| `summary.ipynb` | figures for FINDINGS.md, built from `results/` (saved with outputs, so it renders on GitHub) |
| `fft_reconstruction_summary.ipynb` | executed figures and paired comparisons for the FFT-only training ablation |
| `paths.py` | locations of data and run outputs |

## Setup

The experiments use the repository's own environment plus one dependency group:

```bash
uv sync --group experiments
```

Results were produced with Python 3.11, torch 2.5.1, numpy 2.4.6, scipy 1.17.1, pandas 2.3.3,
pyarrow 25.0.0, matplotlib 3.11.0 and statsmodels 0.15.0, as pinned in `uv.lock`.

Run outputs (checkpoints, caches, per-run tables) go to `experiments/decomposition/runs/`, which git ignores.
Set `DECOVAE_RUNS` to put them elsewhere. Scripts are run from their own folder, for example
`cd experiments/decomposition/benchmark && python runner.py validate`.

## Data

**Synthetic data** is generated by the code with fixed seeds; true components and the true noise
variance are stored next to every series and are used only in metrics.

- `benchmark/data.py`: 45 base scenarios (trend none / linear / kink × period 0, 12, 24, 48, 96 ×
  noise σ 0.1, 0.3, 0.6), held-out stress scenarios, the `synthetic_v2` training mixture
  (40 % base, 20 % fractional or dual periods, 20 % predictable heteroskedasticity, 10 % AR noise,
  10 % amplitude drift) and a diagnostic suite of 29 one-mechanism-at-a-time cases.
- `benchmark/h1_data.py`: noise with a known volatility state (GARCH, stochastic volatility,
  Markov regimes, homoskedastic and level-dependent controls) for testing H1.
- Context T = 512, horizon L = 96 in the existing benchmark; the isolated `fft_reconstruction/`
  ablation also tests horizons 128 and 256 using shared paths.

**Real data** is the pretraining corpus produced by `convert_data.sh` (`decovaefm/data/unified_converter.py`).
Point `DECOVAE_VER0` to the folder with `manifest.json` (default: `<repo>/data`). The corpus has
566,826 series from 17 sources: Electricity, KDD_Cup_2018, London_Smart_Meters, M4_Daily,
M4_Monthly, M4_Weekly, Pedestrian_Counts, Q-TRAFFIC, Solar, Uber_TLC, Wind_Farms,
azure_vm_traces_2017, borg_cluster_data_2011, largest_2017, mexico_city_bikes, ushcn_daily,
weatherbench_weekly. Series shorter than 2048 points are dropped. The 90 / 5 / 5 train / val / test
split is by series, not by time, so the test split is not a zero-shot benchmark.

Real windows used here: one window per series from the test split of Electricity,
London_Smart_Meters, Q-TRAFFIC, Solar and M4_Daily (`data.real_windows`). Models trained on
synthetic data are evaluated on them without fine-tuning.

## Model variants (`benchmark/`)

All variants share the original encoders, trend decoder and σ-head, d_model 64, 2 encoder and 2
decoder layers, 4 heads, patch = stride = 16, Top-K = 16, Gaussian NLL on reconstruction and
forecast plus 0.01 · KL.

| arm | input decomposition | seasonal decoder | noise latent Z_n in the σ-head |
|---|---|---|---|
| A | original learnable multi-scale MA + Top-K | original (Top-K bins remapped to T+L) | yes |
| B | original | original | no (noise encoder removed, NLL kept) |
| C | period-aware (`period_decomp`) | original | yes |
| D | period-aware | original | no |
| Cf | period-aware | continuous-frequency Fourier at the estimated periods + learned correction | yes |
| Df | period-aware | as Cf | no |

Training: AdamW 1e-3, batch 32, gradient clipping 1.0, early stopping on validation CRPS with
patience 10, at most 60 epochs (10 for `pilot`). Test metrics use 128 samples, each a latent draw
followed by an observation draw. Every run writes `provenance.json` (configuration, library
versions, seeds, source hashes) and a snapshot of the sources.

Data generation, the algorithmic decompositions and evaluation of a saved checkpoint are
deterministic. Training on a GPU is not bit-exact across runs (CUDA kernels), so retrained models
reproduce the reported metrics up to small run-to-run differences.

## Running

The FFT-only ablation has its own [protocol and commands](fft_reconstruction/README.md).
Run `python experiments/decomposition/fft_reconstruction/train.py --profile full` from the repository
root, then `python experiments/decomposition/fft_reconstruction/report.py` to build the CSV summaries
and executed notebook. It imports the current model and the unchanged benchmark loss; the source
snapshot records the actual local environment, which differs from `uv.lock` for the published FFT grid.

Fast, CPU, no training:

```bash
cd experiments/decomposition/checks
python seasonal_decoder_check.py 32      # identity-decoder error of the original seasonal path
python decomp_checks.py                  # MA frequency response, softmax init, bin transfer
python seasonal_split.py                 # amplitude factor vs frequency rounding

cd ../benchmark
python runner.py validate                # unit tests
python h1_headroom.py --profile h1check_strong   # oracle CRPS gain of knowing the true volatility
```

Minutes to tens of minutes on CPU (multiprocessing):

```bash
cd experiments/decomposition/period_decomp
python run_synthetic.py                  # period-aware vs original decomposition, synthetic
python run_ver0.py                       # detected periods on the real corpus (needs DECOVAE_VER0)
```

Training (a GPU is strongly recommended; a `night` / `v2night` run takes from tens of minutes to
hours per arm and seed):

```bash
cd experiments/decomposition/benchmark
python runner.py train --profile v2night --arm A --seed 0 --run-id v2_A_s0 --real   # --real also fixes the real windows
python runner.py train --profile v2night --arm Cf --seed 0 --run-id v2_Cf_s0
python evaluate_diagnostics.py v2_A_s0                    # 29-case diagnostic suite (generated on first use)
python interventions.py v2_A_s0 v2_Cf_s0 --out interventions_v2
python real_transfer_eval.py v2_A_s0 v2_Cf_s0 --windows-run v2_A_s0 --out real_transfer_v2
```

To re-run the figures: `uv run --with jupyterlab jupyter lab experiments/decomposition/summary.ipynb`
(it reads only `results/`; figure 3 recomputes one example in a few seconds).

`pinn/run_all.sh` runs the structural-constraint grid (8 variants × 3 seeds);
`checks/notebook_repro.py <kl_weight> <out_prefix>` reproduces the debug notebook.

Summaries over several runs: `summarize_diagnostics.py`, `summarize_stress.py`,
`diagnostics.py factor`, `fourier_report.py` (see `--help` of each).
